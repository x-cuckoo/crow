# Challenge Proposals

Use this when the user already has a design or implementation idea.

- Do not treat the proposed solution as correct or optimal by default.
- Compare it with viable alternatives using the current code, constraints, and design-quality criteria.
- Propose a materially better design proactively; do not favor a path merely because it is shorter, faster, or more abstract.
- Explain concrete tradeoffs in correctness, cohesion, coupling, boundaries, cognitive complexity, operability, compatibility, and maintenance.
- If the proposal has the best total fit, say why.
